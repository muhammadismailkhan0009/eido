# Project Map

> Navigation cache. Source files are authoritative.

## Project
Eido is a Nim-written native compiler for a Java-like language, lowering typed/resolved HIR to generated Nim and native code.

## Areas
- `src/compiler/frontend/` — lexing, AST, parsing; start: `scanner.nim`, `expression_parser.nim`
- `src/compiler/semantic/` — name resolution/type analysis; start: `program_analysis.nim`, `expression_analysis.nim`
- `src/compiler/types/` — language semantic types/contracts; start: `model.nim`
- `src/compiler/hir/` — typed/resolved backend-facing representation; start: `expressions.nim`, `program.nim`
- `src/compiler/backend/nim/` — HIR→Nim emission and native toolchain; start: `program_emitter.nim`
- `tests/compiler/` — compiler tests mirroring production ownership; aggregate: `compiler_test_suite.nim`
- `tests/parallel_test_runner.nim` — CPU-adaptive compile-once/process-parallel `nimble test` orchestrator
- `tests/features/` — user-facing language variant catalogs; start: `README.md`; expression coverage starts at `expression/README.md`, control-flow coverage at `control_flow/README.md`

## Routes
- Boolean operators -> `frontend/lexer/keywords/boolean_operators.nim` -> AST operator vocabulary in `expressions.nim` -> `frontend/parser/expression/boolean_operators.nim` -> HIR operator vocabulary in `hir/expressions.nim` -> `semantic/analysis/expression/boolean_operators.nim` -> `backend/nim/emitter/expression/boolean_operators.nim`
- conditionals -> `frontend/lexer/keywords/conditional_statements.nim` -> AST statement vocabulary -> `frontend/parser/statement/conditional_statements.nim` -> HIR statement vocabulary -> `semantic/analysis/statement/conditional_statements.nim` -> `backend/nim/emitter/statement/conditional_statements.nim` -> `tests/features/control_flow/conditional_variants_test.nim` / `else_if_variants_test.nim`
- while loops -> `frontend/lexer/keywords/while_statements.nim` -> AST statement vocabulary -> `frontend/parser/statement/while_statements.nim` -> HIR statement vocabulary -> `semantic/analysis/statement/while_statements.nim` -> `backend/nim/emitter/statement/while_statements.nim` -> `tests/features/control_flow/while_variants_test.nim`
- classic for loops -> `frontend/lexer/keywords/for_statements.nim` -> AST `skFor` -> `frontend/parser/statement/for_statements.nim` -> HIR `hskFor` -> `semantic/analysis/statement/for_statements.nim` -> `backend/nim/emitter/statement/for_statements.nim` -> `tests/features/control_flow/for_variants_test.nim`
- loop control -> `frontend/lexer/keywords/loop_control_statements.nim` -> AST `skBreak`/`skContinue` -> `frontend/parser/statement/loop_control_statements.nim` -> semantic loop-depth validation -> HIR `hskBreak`/`hskContinue` -> `backend/nim/emitter/statement/loop_control_statements.nim` -> `tests/features/control_flow/loop_control_variants_test.nim`
- class declarations -> `frontend/lexer/keywords/class_declarations.nim` -> AST `ClassDecl`/`FieldDecl` -> `frontend/parser/declaration/class_declarations.nim` -> nominal registry `semantic/symbols/classes.nim` -> `semantic/analysis/class_analysis.nim` -> HIR `HirClass`/`HirField` -> `tests/features/classes/class_declaration_variants_test.nim`
- class construction -> AST `ekConstruct` -> `frontend/parser/expression/construction_expressions.nim` -> `semantic/analysis/expression/construction_expressions.nim` using resolved class-field symbols -> HIR `hekConstruct` -> `backend/nim/emitter/expression/construction_expressions.nim` + `class_emitter.nim` -> `tests/features/classes/class_construction_variants_test.nim`
- expression parsing -> `frontend/parser/expression/README.md` -> the owning semantic module -> thin `expression_parser.nim` coordinator
- expression semantics -> `semantic/analysis/expression/README.md` -> the owning semantic module -> thin `expression_analysis.nim` coordinator
- primitive types/literals -> `model.nim` -> `token.nim`/`keywords.nim`/`scanner.nim` -> `frontend/parser/expression/literal_expressions.nim` -> `semantic/analysis/expression/literal_expressions.nim` / `expected_types.nim` -> `type_emitter.nim`
- function parameters/results/calls -> `declarations.nim` -> `declaration_parser.nim` -> `program_analysis.nim`/`function_analysis.nim` -> HIR declarations -> `function_emitter.nim`
- add language behavior -> owning compiler test -> implementation -> matching feature catalog -> `nimble test`
- inspect supported variants -> `tests/features/README.md`; expressions start at `tests/features/expression/README.md`, control flow at `tests/features/control_flow/README.md`

## Flows
- compile: Eido source -> lexer -> parser/AST -> semantic analysis -> typed/resolved HIR -> Nim emitter -> Nim toolchain -> native executable
- feature acceptance: Eido source -> compiler pipeline -> generated Nim -> `nim e` -> assertion
- full test run: compile aggregate once with adaptive `--parallelBuild:N` -> compiler suites + individual feature tests -> isolated parallel processes via `execProcesses`
