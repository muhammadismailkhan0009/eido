# Project Map

> Navigation cache. Source files are authoritative.

## Project
Eido is a Nim-written native compiler for a Java-like language. The compiler now operates on explicit multi-source projects, lowers typed/resolved HIR to generated Nim/native code, and exposes protocol-neutral tooling services for CLI/LSP/MCP growth.

## Areas
- `compiler/src/source/` — source identity/text/span model; start: `source_unit.nim`, `span.nim`
- `compiler/src/project/` — compiler-level project/target model; start: `model.nim`
- `compiler/src/frontend/` — per-source lexing/AST/parsing plus project AST assembly; start: `scanner.nim`, `expression_parser.nim`, `project_parser.nim`
- `compiler/src/semantic/` — name resolution/type analysis; start: `program_analysis.nim`, `expression_analysis.nim`
- `compiler/src/types/` — language semantic types/contracts; start: `model.nim`
- `compiler/src/hir/` — typed/resolved backend-facing representation; start: `expressions.nim`, `program.nim`
- `compiler/src/backend/nim/` — HIR→Nim emission and native toolchain; start: `program_emitter.nim`
- `compiler/src/tooling/` — protocol-neutral project check/compile/editor-query services for CLI/MCP/LSP/CI; `checkProject` returns structured diagnostics + analyzed HIR, `hover_service.nim` derives semantic hover, `formatting_service.nim` owns canonical formatting, and `symbol_service.nim` + `tooling/symbols/` own semantic declaration/reference identity for highlighting/navigation
- `compiler/tests/` — compiler-internal and language-facing conformance tests; aggregate: `compiler_test_suite.nim`; runner: `parallel_test_runner.nim`
- `tools/cli/src/` — temporary Nim bootstrap `eido` adapter used until Eido CLI parity
- `tools/cli/eido/` — permanent CLI implementation written in Eido; currently help/version/unknown-command behavior
- `tools/mcp/` — planned MCP protocol adapter over compiler tooling; no MCP behavior implemented yet
- `tools/lsp/src/` — working editor-neutral stdio LSP adapter: JSON-RPC lifecycle, full document overlays, project-aware live diagnostics, semantic hover, semantic tokens, go-to-definition, and document formatting; compiler semantics remain in protocol-neutral tooling
- `tools/vscode/` — thin VS Code/Cursor client for `eido-lsp`, .eido language registration/TextMate + semantic coloring, hover/definition/formatting via LSP, and CLI-backed Check/Build/Run commands
- `stdlib/` — foundational APIs guaranteed with the Eido SDK; Eido-facing sources under `stdlib/src/`, backend support under `stdlib/native/`
- `packages/` — higher-level ordinary Eido libraries built above stdlib
- `installer/` — SDK assembly/installation ownership
- `tests/integration/` — cross-component SDK/tool/library integration tests
- `examples/` — executable Eido examples
- `docs/` — architecture, testing, feature, and v0 specification documentation

## Ownership
- `source/source_unit.nim` — `SourceId` + `SourceUnit(id,path,text)` for project-local source identity
- `source/span.nim` — source-aware spans carrying source id/path plus offsets/line/column; `coverSpan` preserves file identity for composite AST spans
- `project/model.nim` — `EidoProject`, explicit source set, and `ptExecutable` / `ptLibrary` target kind
- `diagnostics/model.nim` — protocol-neutral diagnostic record: code/severity/message/optional source span
- `diagnostics/codes.nim` — stable diagnostic-code constants; currently EIDO1000 generic source, EIDO2001 empty project, EIDO2002 missing main
- `diagnostics/errors.nim` — `CompilerError` bridge plus `failAt`/project `fail`; embeds structured diagnostics while remaining ValueError-compatible
- `diagnostics/formatting.nim` — human rendering such as `path:line:column error CODE: message`
- `token.nim` — canonical token vocabulary including `tkNative`, String type/literal tokens, and `tkSet`/`tkSelf`/`tkCopy`/`tkRef`; `keywords.nim` — keyword dispatch including `native`, built-in `String`, and other reserved words
- `frontend/lexer/keywords/native_functions.nim` — `native` declaration keyword classification
- `frontend/parser/declaration/native_function_declarations.nim` — reusable bodyless `native function ...;` grammar for top-level declarations and class-owned native methods
- `frontend/lexer/keywords/boolean_operators.nim` — Boolean word keyword classification
- `frontend/lexer/keywords/conditional_statements.nim` — `if`/`else` keyword classification
- `frontend/lexer/keywords/while_statements.nim` — `while` keyword classification
- `frontend/lexer/keywords/for_statements.nim` — classic `for` keyword classification
- `frontend/lexer/keywords/loop_control_statements.nim` — `break`/`continue` keyword classification
- `frontend/lexer/keywords/class_declarations.nim` — `class` keyword classification
- `frontend/lexer/keywords/interface_declarations.nim` + `frontend/parser/declaration/interface_declarations.nim` — `interface`/`implements`/`extends` vocabulary and bodyless interface contract grammar
- `frontend/ast/type_references.nim` — recursive source type applications (`Box<Int>`, `Result<List<User>, Error>`) plus class type-parameter declarations
- `frontend/parser/type_references.nim` — shared recursive type-reference grammar, including module-qualified nominal paths such as `payments.Result`
- `semantic/symbols/interfaces.nim` + `semantic/symbols/nominals.nim` — interface contract symbols and the combined nominal class/interface type environment, including explicit conformance and assignability
- `semantic/analysis/interface_analysis.nim` — interface inheritance, signature resolution, explicit class conformance, and inherited-contract validation; ordinary class types are valid interface signature types

- `backend/nim/emitter/nominal_type_emitter.nim` — emits class/interface layouts in one Nim type section so public class/interface APIs may reference each other recursively
- `docs/features/interfaces.md` — authoritative interface/conformance/runtime-dispatch guide
- `project/modules/model.nim` + `manifest_parser.nim` + `loader.nim` — mandatory `module.yaml` schema, explicit source/child ownership, canonical module identities, dependency resolution, and DAG validation
- `semantic/modules/architecture_validation.nim` + `semantic/modules/validation/` — module architecture coordinator, canonical declaration registry, visibility/interface/provider/source-usage validation, and transitive API surfaces
- `semantic/modules/qualification/` + `semantic/modules/validation/qualification.nim` — focused post-surface name-resolution pass that canonicalizes types, constructions, static class paths, and module-local functions while preserving lexical local shadowing
- `docs/features/modules.md` — authoritative module manifest/schema and parent-child propagation guide
- `semantic/generics/class_specialization.nim` — validates generic templates, preserves interface conformance, and statically materializes used concrete class applications before ordinary semantic analysis
- `semantic/analysis/optional_paths.nim` + `semantic/symbols/scope.nim` — exact lexical presence-proof paths for `if <path> exists`; proofs are block-local and intentionally mutation-insensitive in the initial model

## Routes
- Boolean operators -> `frontend/lexer/keywords/boolean_operators.nim` -> AST operator vocabulary in `expressions.nim` -> `frontend/parser/expression/boolean_operators.nim` -> HIR operator vocabulary in `hir/expressions.nim` -> `semantic/analysis/expression/boolean_operators.nim` -> `backend/nim/emitter/expression/boolean_operators.nim`
- conditionals -> `frontend/lexer/keywords/conditional_statements.nim` -> AST statement vocabulary -> `frontend/parser/statement/conditional_statements.nim` -> HIR statement vocabulary -> `semantic/analysis/statement/conditional_statements.nim` -> `backend/nim/emitter/statement/conditional_statements.nim` -> `compiler/tests/features/control_flow/conditional_variants_test.nim` / `else_if_variants_test.nim`
- while loops -> `frontend/lexer/keywords/while_statements.nim` -> AST statement vocabulary -> `frontend/parser/statement/while_statements.nim` -> HIR statement vocabulary -> `semantic/analysis/statement/while_statements.nim` -> `backend/nim/emitter/statement/while_statements.nim` -> `compiler/tests/features/control_flow/while_variants_test.nim`
- classic for loops -> `frontend/lexer/keywords/for_statements.nim` -> AST `skFor` -> `frontend/parser/statement/for_statements.nim` -> HIR `hskFor` -> `semantic/analysis/statement/for_statements.nim` -> `backend/nim/emitter/statement/for_statements.nim` -> `compiler/tests/features/control_flow/for_variants_test.nim`
- loop control -> `frontend/lexer/keywords/loop_control_statements.nim` -> AST `skBreak`/`skContinue` -> `frontend/parser/statement/loop_control_statements.nim` -> semantic loop-depth validation -> HIR `hskBreak`/`hskContinue` -> `backend/nim/emitter/statement/loop_control_statements.nim` -> `compiler/tests/features/control_flow/loop_control_variants_test.nim`
- set mutation -> lexer `tkSet` -> AST `skAssign` with expression target -> `parseSetStmt` / for-update parsing -> semantic target validation -> class relationship mutation helper when the target is class-valued -> HIR `hskAssign` or `hskFieldSet` -> statement emitter -> `compiler/tests/features/set_variants_test.nim` / class relationship coverage in `compiler/tests/features/classes/class_copy_ref_variants_test.nim`
- class declarations -> `frontend/lexer/keywords/class_declarations.nim` -> AST `ClassDecl`/`FieldDecl` -> `frontend/parser/declaration/class_declarations.nim` -> nominal registry `semantic/symbols/classes.nim` -> `semantic/analysis/class_analysis.nim` -> HIR `HirClass`/`HirField` -> `compiler/tests/features/classes/class_declaration_variants_test.nim`
- generic classes -> recursive `TypeRef` syntax + `class Name<T, ...>` -> `semantic/generics/class_specialization.nim` validates templates and materializes concrete applications transitively -> ordinary nominal class analysis/HIR/backend -> `generic_class_parser_test.nim` / `generic_class_analysis_test.nim` / `generic_class_emitter_test.nim` / `generic_class_variants_test.nim`
- class construction -> source `Type { field = expression; }` -> AST `ekConstruct` -> `frontend/parser/expression/construction_expressions.nim` -> semantic exact-field/type validation plus explicit `copy`/`ref` for existing class-valued field inputs -> HIR `hekConstruct`/`hekClassRelation` -> construction/class/copy emitters -> `compiler/tests/features/classes/class_construction_variants_test.nim` / `class_copy_ref_variants_test.nim`
- class field access -> lexer `tkDot` -> AST `ekFieldAccess` -> `frontend/parser/expression/field_access_expressions.nim` -> `semantic/analysis/expression/field_access_expressions.nim` -> HIR `hekFieldAccess` -> `backend/nim/emitter/expression/field_access_expressions.nim` -> `compiler/tests/features/classes/class_field_access_variants_test.nim`
- class methods -> class-body `function` AST -> `semantic/analysis/method_classification.nim` infers `mkStatic` when the full body is self-free or `mkInstance` when any nested expression/statement reaches explicit `self`; `Type.method(...)` resolves only static methods with no receiver HIR, while `value.method(...)` resolves only instance methods with a receiver; backend preserves that distinction -> `class_static_method_variants_test.nim` / `class_method_variants_test.nim` / `self_receiver_variants_test.nim`
- expression parsing -> `frontend/parser/expression/README.md` -> the owning semantic module -> thin `expression_parser.nim` coordinator
- expression semantics -> `semantic/analysis/expression/README.md` -> the owning semantic module -> thin `expression_analysis.nim` coordinator
- primitive types/literals -> `model.nim` -> `token.nim`/`keywords.nim`/`scanner.nim` -> `frontend/parser/expression/literal_expressions.nim` -> `semantic/analysis/expression/literal_expressions.nim` / `expected_types.nim` -> `type_emitter.nim`
- String values -> lexer String type/literal tokens -> decoded AST `ekString` -> semantic `etString`/HIR `hekString` -> String `+` and content equality rules -> Nim `string` / `&` backend -> `compiler/tests/features/string_variants_test.nim`
- class identity flow -> lexer `tkCopy`/`tkRef` -> AST `ekClassRelation` -> dedicated relation analysis/provenance -> local binding, construction field, local `set`, or own-field `set` relationship boundary -> HIR `hekClassRelation` -> `ref` identity pass-through or generated graph copier -> `compiler/tests/features/classes/class_copy_ref_variants_test.nim`
- function parameters/results/calls -> `declarations.nim` -> nominal-aware `declaration_parser.nim`/`type_resolution.nim` -> signature collection/body provenance checks -> HIR declarations -> function/method emitters; class parameters preserve identity and class results must be detached
- native functions -> lexer `tkNative` -> reusable bodyless native declaration parser -> AST `isNative` -> primitive/String-only ABI validation -> top-level declarations resolve through function symbols and map to `eido_native_<sourceName>`; class-owned native declarations resolve as `mkStatic` methods with `isNative`, map to `eido_native_method_<Owner>_<method>`, carry no receiver, and emit no Eido/Nim body; any native declaration causes bundled `eido_native` import
- Eido CLI dogfood -> direct class-owned native `Process.*` + `Console.*` declarations -> `tools/cli/eido/main.eido` -> bootstrap compiler -> bundled native ABI -> permanent CLI help/version/error/exit behavior; no Eido wrapper layer sits between the public stdlib API and native support
- project compilation -> `SourceUnit[]` + `ProjectTarget` -> `frontend/parser/project_parser.nim` -> merged AST declaration universe -> generic-class static specialization -> target-aware `semantic/analysis/program_analysis.nim` -> HIR (`hasMain` for executables) -> backend
- structured diagnostics -> parser/semantic `failAt` or project `fail` -> `CompilerError(CompilerDiagnostic)` -> `tooling.checkProject` converts expected compiler failure to `ProjectCheckResult.diagnostics`; unexpected invariants propagate
- CLI check -> `eido check <files...>` -> `cli/check_command.nim` -> executable `EidoProject` -> `tooling.checkProject` -> human diagnostic formatting; no emitter/toolchain invocation
- tool-adapter compilation -> `tools/cli/src/cli/build_command.nim` builds `SourceUnit[]` -> `compiler/src/tooling/compiler_service.nim` -> project compiler -> Nim backend toolchain; future MCP/LSP adapters reuse the same project/tooling boundary
- add language behavior -> owning compiler test -> implementation -> matching feature catalog -> `nimble test`
- inspect supported variants -> `compiler/tests/features/README.md`; expressions start at `compiler/tests/features/expression/README.md`, control flow at `compiler/tests/features/control_flow/README.md`

## Flows
- compile: CLI/tool adapter -> compiler tooling API -> `EidoProject` -> per-source lexer/parser -> merged AST -> generic-class static specialization -> target-aware semantic analysis -> typed/resolved HIR -> Nim emitter -> Nim toolchain -> native executable (for executable targets)
- check: CLI/LSP/MCP/CI adapter -> compiler tooling API -> `EidoProject` -> parser + semantic analysis -> `ProjectCheckResult`; current fail-fast compiler yields at most one diagnostic per run, but the public result is sequence-shaped for future recovery
- feature acceptance: Eido source -> compiler pipeline -> generated Nim -> `nim e` -> assertion
- full test run: compile aggregate once with adaptive `--parallelBuild:N` -> compiler suites + individual feature tests -> isolated parallel processes via `execProcesses` -> bootstrap CLI integration -> Eido-written CLI dogfood integration
