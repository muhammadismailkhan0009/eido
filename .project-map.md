# Project Map

> Navigation cache. Source files are authoritative.

## Project
Eido is a Nim-written native compiler for a Java-like language, currently lowering typed/resolved HIR to generated Nim and then native code.

## Areas
- `src/compiler/frontend/` — lexing, AST, and parsing; start: `scanner.nim`, `program_parser.nim`
- `src/compiler/semantic/` — symbol resolution and semantic analysis; start: `program_analysis.nim`
- `src/compiler/types/` — language-level type/result contracts; start: `model.nim`
- `src/compiler/hir/` — typed/resolved backend-facing representation; start: `program.nim`
- `src/compiler/backend/nim/` — HIR→Nim emission and Nim toolchain integration; start: `program_emitter.nim`
- `tests/compiler/` — responsibility-aligned internal compiler BDD tests; aggregate: `compiler_test_suite.nim`
- `tests/features/` — language-facing executable variant catalog; start: `README.md`, `function_variants_test.nim`

## Ownership
src/compiler/types/
- `model.nim` — primitive semantic types and type-category predicates
- `function_result.nim` — zero-or-one function-result contract

src/compiler/semantic/analysis/
- `expression_analysis.nim` — expression typing, call argument checking, integer-literal contextual typing
- `statement_analysis.nim` — declaration/assignment/call/return semantic rules
- `program_analysis.nim` — first-pass function signature collection and forward-call support

src/compiler/backend/nim/emitter/
- `type_emitter.nim` — Eido primitive→Nim representation mapping
- `program_emitter.nim` — complete generated Nim program and main harness

## Routes
- change primitive types/literals -> `model.nim` -> `token.nim`/`keywords.nim`/`scanner.nim` -> `expression_parser.nim` -> `expression_analysis.nim` -> `type_emitter.nim`
- change comparison expressions -> `token.nim`/`scanner.nim` -> AST/HIR binary operators -> `expression_parser.nim` -> `expression_analysis.nim` -> `expression_emitter.nim`
- change function parameters/results/calls -> `declarations.nim` -> `declaration_parser.nim` -> `program_analysis.nim`/`function_analysis.nim` -> HIR declarations -> `function_emitter.nim`
- add language behavior -> owning BDD test under `tests/compiler/` first -> compiler change -> matching user-visible scenario under `tests/features/` -> `nimble test`
- inspect supported/tested language variants -> `tests/features/README.md` -> relevant `*_variants_test.nim`

## Flows
- compile: Eido source -> lexer -> parser/AST -> semantic analysis -> typed/resolved HIR -> Nim emitter -> Nim toolchain -> native executable
- function calls: signatures collected in `program_analysis.nim` before bodies -> calls resolved/type-checked in `expression_analysis.nim` -> resolved `HirCall` -> Nim emitter

## Invariants
- Expression precedence is grouping -> unary `-` -> `* /` -> `+ -` -> `< <= > >=` -> `== !=`; equal-precedence binary operators evaluate left-to-right. Unary `-` is recursive and valid only for Int/Float, while all comparisons return Bool. Equality requires matching primitive types; ordered comparison requires matching Byte/Short/Int/Float types; integer literals may contextually adopt an opposite Byte/Short comparison operand. `()`, `[]`, `{}` are equivalent matching grouping delimiters. Derived math such as powers/roots belongs in libraries.
- Supported primitives are Bool, Byte, Short, Int, Float, Char; Int is signed 64-bit and replaces a separate Long type, Float is 64-bit and replaces a separate Double type, and numeric width suffixes L/F/D are rejected.
- Compiler tests are organized by compiler responsibility; feature files are navigation catalogs whose suites name narrow semantic rules/variant families rather than catch-all categories or historical feature numbers. Feature scenarios execute generated Nim through `nim e` for speed, while dedicated pipeline tests retain real native compilation coverage. New behavior is BDD-first and the full suite runs with `nimble test`.
- Backends consume HIR, not raw AST; Eido semantic types must not depend on Nim representations.
- Direct new-binding initialization from a bare existing identifier is rejected until explicit `copy`/`ref` semantics are implemented.
- Function inputs are 0..N parameters; function results are 0..1 values.
