# Project Map

> Navigation cache. Source files are authoritative.

## Project
Eido is a Nim-written native compiler for a Java-like language, lowering typed/resolved HIR to generated Nim and native code.

## Areas
- `src/compiler/frontend/` — lexing, AST, parsing; start: `scanner.nim`, `expression_parser.nim`
- `src/compiler/semantic/` — name resolution/type analysis; start: `program_analysis.nim`, `expression_analysis.nim`
- `src/compiler/types/` — language semantic types/contracts; start: `model.nim`
- `src/compiler/hir/` — typed/resolved backend-facing representation; start: `expressions.nim`, `program.nim`
- `src/compiler/backend/nim/` — HIR→Nim emission and native toolchain; start: `program_emitter.nim`
- `tests/compiler/` — compiler tests mirroring production ownership; aggregate: `compiler_test_suite.nim`
- `tests/features/` — user-facing language variant catalogs; start: `README.md`; expression coverage starts at `expression/README.md`

## Ownership
- `token.nim` — canonical token vocabulary; `keywords.nim` — keyword dispatch
- `frontend/lexer/keywords/boolean_operators.nim` — Boolean word keyword classification
- `expression_parser.nim` — thin expression entry point, precedence assembly, and shared binary-span helper
- `frontend/parser/expression/literal_expressions.nim` — primitive literal AST parsing/Char decoding
- `frontend/parser/expression/call_expressions.nim` — call expressions and arguments
- `frontend/parser/expression/grouping_expressions.nim` — matching `() [] {}` grouping
- `frontend/parser/expression/primary_expressions.nim` — primary dispatch and identifiers
- `frontend/parser/expression/unary_negation.nim` — recursive unary numeric negation
- `frontend/parser/expression/arithmetic_operators.nim` — multiplicative/additive parsing
- `frontend/parser/expression/comparison_operators.nim` — ordered/equality comparison parsing
- `frontend/parser/expression/boolean_operators.nim` — `not/and/or` parsing and precedence
- `expression_analysis.nim` — expression semantic dispatch/shared analysis
- `semantic/analysis/expression/boolean_operators.nim` — Boolean type rules and HIR lowering
- `expression_emitter.nim` — expression emission dispatch/shared rendering
- `backend/nim/emitter/expression/boolean_operators.nim` — Boolean HIR→Nim rendering
- `feature_test_support.nim` — fast feature execution via generated Nim and `nim e`
- `compiler_pipeline_test.nim` — real native-compilation boundary coverage

## Routes
- Boolean operators -> `frontend/lexer/keywords/boolean_operators.nim` -> AST operator vocabulary in `expressions.nim` -> `frontend/parser/expression/boolean_operators.nim` -> HIR operator vocabulary in `hir/expressions.nim` -> `semantic/analysis/expression/boolean_operators.nim` -> `backend/nim/emitter/expression/boolean_operators.nim`
- expression parsing -> `frontend/parser/expression/README.md` -> the owning semantic module -> thin `expression_parser.nim` coordinator
- primitive types/literals -> `model.nim` -> `token.nim`/`keywords.nim`/`scanner.nim` -> `frontend/parser/expression/literal_expressions.nim` -> `expression_analysis.nim` -> `type_emitter.nim`
- function parameters/results/calls -> `declarations.nim` -> `declaration_parser.nim` -> `program_analysis.nim`/`function_analysis.nim` -> HIR declarations -> `function_emitter.nim`
- add language behavior -> owning compiler test -> implementation -> matching feature catalog -> `nimble test`
- inspect supported variants -> `tests/features/README.md`; for expressions use `tests/features/expression/README.md` first, then the owning focused `*_variants_test.nim`

## Flows
- compile: Eido source -> lexer -> parser/AST -> semantic analysis -> typed/resolved HIR -> Nim emitter -> Nim toolchain -> native executable
- feature acceptance: Eido source -> compiler pipeline -> generated Nim -> `nim e` -> assertion
