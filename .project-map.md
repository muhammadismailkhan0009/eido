# Project Map

> Navigation cache. Source files are authoritative.

## Project
Eido is a Nim-written native compiler for a Java-like language, lowering typed/resolved HIR to generated Nim and native code.

## Areas
- `src/compiler/frontend/` — lexing, AST, parsing; start: `scanner.nim`, `expression_parser.nim`
- `src/compiler/semantic/` — name resolution/type analysis; start: `program_analysis.nim`, `expression_analysis.nim`
- `src/compiler/types/` — language semantic types/contracts; start: `model.nim`
- `src/compiler/hir/` — typed/resolved backend-facing representation; start: `expressions.nim`, `program.nim`
- `src/compiler/backend/nim/` — HIR→Nim emission and native toolchain; start: `program_emitter.nim`
- `tests/compiler/` — responsibility-aligned compiler tests; aggregate: `compiler_test_suite.nim`
- `tests/features/` — user-facing language variant catalog; start: `README.md`, `expression_variants_test.nim`

## Ownership
- `keywords.nim` / `token.nim` — reserved-word/token vocabulary
- `expression_parser.nim` — expression grammar and precedence
- `expression_analysis.nim` — expression typing, calls, contextual integer typing, comparisons/Boolean operators
- `expression_emitter.nim` — HIR expression/operator rendering to Nim

- `feature_test_support.nim` — fast language-facing execution via generated Nim and `nim e`
- `compiler_pipeline_test.nim` — real native-compilation boundary coverage

## Routes
- primitive types/literals -> `model.nim` -> `token.nim`/`keywords.nim`/`scanner.nim` -> `expression_parser.nim` -> `expression_analysis.nim` -> `type_emitter.nim`
- expression operators/precedence -> `token.nim`/`keywords.nim` -> `expressions.nim` (AST) -> `expression_parser.nim` -> `expressions.nim` (HIR) -> `expression_analysis.nim` -> `expression_emitter.nim`
- function parameters/results/calls -> `declarations.nim` -> `declaration_parser.nim` -> `program_analysis.nim`/`function_analysis.nim` -> HIR declarations -> `function_emitter.nim`
- add language behavior -> owning test under `tests/compiler/` -> implementation -> matching semantic suite in `tests/features/` -> `nimble test`
- inspect supported variants -> `tests/features/README.md` -> relevant `*_variants_test.nim`

## Flows
- compile: Eido source -> lexer -> parser/AST -> semantic analysis -> typed/resolved HIR -> Nim emitter -> Nim toolchain -> native executable
- feature acceptance: Eido source -> compiler pipeline -> generated Nim -> `nim e` -> assertion
- function calls: `program_analysis.nim` collects signatures first -> `expression_analysis.nim` resolves/types calls -> HIR call -> Nim emitter
